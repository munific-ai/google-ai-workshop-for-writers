Google Cloud AI workshop for writers
===

記者向けの Gemini / Google Workspace with Gemini / Gemini Enterprise ハンズオン。
**60 分（20 分 × 3 パート）** で、個人の生産性向上と組織の業務効率化の違いが体験できます。

---

## コンセプト

AI に任せるのは、取材の準備・下調べ・図表づくり・事実確認・表記統一といった**周辺業務**に絞りました。中核の執筆は人が担い、周辺をエージェントが引き受ける —— この構図はそのまま一般企業の読者にも置き換わります。

## 全体の骨格

**Part 2 と Part 3 で「仕事の種類」を変え、その違いを体感いただきます。**

|                    | Part 2                             | Part 3                                 |
| ------------------ | ---------------------------------- | -------------------------------------- |
| 何をするか         | **手元のデータを、自分で加工する** | **散らばった情報を、探さずに横断する** |
| ファイルを開くのは | **参加者**                         | **誰も開かない**                       |
| 成果物             | 自分のための図表                   | **他人も使えるエージェントチーム**     |
| 対応する価値       | 個人の生産性向上                   | 組織の業務効率化                       |

| Part | 製品                  | いなくてもできるようになる専門職                       |
| ---- | --------------------- | ------------------------------------------------------ |
| 1    | Gemini                | **英語と技術の通訳**（海外の一次情報が読める）         |
| 2    | Workspace with Gemini | **データアナリスト**（手元のデータが図表になる）       |
| 3    | Gemini Enterprise     | **校閲者・情報システム部門**（社内の知識が引き出せる） |

### 題材：AI エージェントの導入効果

記者は特集「**AI エージェント、実証実験から実務へ**」を担当し、導入企業 5 社への取材を終えて、**来週 Google Cloud の AI 担当 VP に取材**する——という設定です。

記事の軸はこうです。

> **実証実験を抜けた先で、業務時間の削減率は 99% から 16% まで開いた。**
> **分けているのは製品ではなく、その業務の判断基準が言語化されているか。**

### 縦串：Part 1 の下調べが、Part 3 の取材質問になる

Part 1 で読む [記事](https://cloud.google.com/transform/5-insights-to-build-your-agentic-ai-advantage-in-2026) は、AI の使われ方を **3 段階**（チャットボット → 単一エージェント → マルチエージェント）で整理しています。

Part 3 で「日本企業はまだ第 1〜2 段階では」と質問しようとすると、横断検索が**社内資料でその前提を訂正します**。**下調べ → 横断 → 裏取り → 質問**が一直線につながります。

### 2 つの山場

**Part 2 — グラフが作れずに詰まる瞬間**

5 社の効果は「約 100 時間 → 約 30 分」「4,500 人時/年 → 450 人時/年」「約 2.5 か月 → 約 1 か月」「16% 減」「公表なし」。**単位がまったく揃っていません。**

参加者が書いている記事の主題は「**判断の基準が言語化されている業務ほど効果が大きい**」でした。そして**グラフを作ろうとした瞬間に、効果の測り方すら揃っていない**という同じ壁にぶつかります。

> このバラつきは作為ではありません。**実在企業の公表値がそのままバラバラ**です。

**Part 3 — マルチエージェントを、自分で作る**

Part 1 の記事の第 3 段階（マルチエージェント）を、参加者が実際に組みます。
**5 体のチーム**——用字用語・事実確認・編集方針・前科制約・統合役——に分けるのは、
取材した**みなも電力が分析工程を分解したのとまったく同じ考え方**です。

**そして 3 年前の自社の失敗**

> **「なお貴媒体は 2023 年 10 月にも、同じ役職名で訂正を掲載しています（COR-2023-0147）」**

この訂正記録は **Google Chat にしか存在しません**。Docs のサイドパネルから Chat を `@` で指定することはできないため、**Part 2 のやり方では構造的に届かなかった**情報です。

## ⚠️ 実在企業の扱い

| 対象                                                                                            | 扱い                                                                                                                |
| ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **取材先 5 社**（東都テレビ／静和精機／みなも電力／京浜運輸／東雲デジタル銀行）と **TECHSCOPE** | **すべて架空**。人物・数値・発言も架空。**仕込みの誤りはすべてここに寄せてある**                                    |
| **公開事例の日本企業**（テレビ朝日／イオンリテール／東京電力EP など）                           | **実在**。**公表済みの事実のみ**を出典 URL 付きで掲載。発言・内部事情・未公表数値は創作せず、**やり取りも作らない** |
| **Google Cloud**                                                                                | **実在**。VP の氏名は設定せず、**取材は物語上「来週」＝未実施**。発言・価格・実績はデータに一切登場しない           |
| **Part 1 で読む記事**                                                                           | **実在**する公開情報                                                                                                |

**「架空の取材先で仕掛けを作り、実在の公開事例で裏を取る」**という二層構造です。実在企業の通信や発言を一切捏造せずに、ワークショップが成立します。これは記者の実務そのものでもあります。

**冒頭スライドでこの点を必ず明示してください。** 記者が参加するため、この一言の有無が信頼に直結します。

架空社名はすべて、実在企業との衝突がないことを検索で確認済みです。
