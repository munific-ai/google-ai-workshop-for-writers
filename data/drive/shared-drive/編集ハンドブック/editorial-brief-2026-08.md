# 特集「データ基盤、実証実験から実務へ」編集方針

**合意者**：三村 健吾（デスク）／佐倉 涼（担当記者）
**掲載予定**：2026年8月17日

> 入稿前に、この方針に照らして自分の原稿を読み返してください。
> 事実が正しくても、方針から外れていれば書き直しになります。

---

## 1. 読者ペルソナ

**情報システム部門の課長クラス（40代）**

- 予算と人員を握っているが、自分では SQL を書かない
- BigQuery は名前を知っている程度。Looker は聞いたことがある程度
- 読む動機は「**うちでもできるのか**」を判断したいから
- ベンダーの宣伝記事にはうんざりしている。売り込まれると閉じる

**この人が読み終わったときに得ているべきもの**
自社が「6 週間で効かせられる側」なのか「半年かかる側」なのかを、自分で判定できる材料。

---

## 2. 主題（これ以外に広げない）

> **導入の速さを分けるのは、製品の性能ではなく導入側の準備である。**

この一文に貢献しない段落は、面白くても削ります。

**特に注意**：AI エージェントや基盤モデルの「未来の話」に寄り道しないこと。
本稿は事例記事であり、技術展望記事ではありません。触れるとしても、主題に接続する範囲にとどめます。

---

## 3. 技術難易度

| 項目             | 方針                                           |
| ---------------- | ---------------------------------------------- |
| 製品名・専門用語 | 出してよい。ただし**初出で一言の説明**を付ける |
| SQL・コード      | **載せない**                                   |
| アーキテクチャ図 | **入れない**（今回は事例記事）                 |
| 数値             | 出典を明示できるものだけ                       |

「情報システム部門の課長が、部内会議でそのまま説明できる」水準を目安にします。

---

## 4. トーン

- **特定製品を持ち上げない。** 本稿は比較記事ではありません
- **導入企業を「進んでいる／遅れている」で序列化しない。** 業種や規制環境の違いは優劣ではありません
- 成功譚にしない。**うまくいった条件**と**そうでない場合に何が起きるか**を等しく書く
- 読者が自社に当てはめて判断できる材料を出す

---

## 5. ⚠️ 炎上リスクの回避（今回もっとも注意する項目）

前回の特集で SNS 上の反発を受けた反省を踏まえます。

### 絶対に避けること

| 避けること                                             | 理由                                                                               |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| **煽り見出し**                                         | 内容と乖離すると、本文を読まない層に切り取られる                                   |
| **「〜すべきだ」「〜は間違っている」**                 | 事例記事で説教をしない。判断は読者がする                                           |
| **取材先の発言を、文脈から切り離して強い主張に見せる** | 取材先との信頼を毀損する。訂正では回復できない                                     |
| **実在製品のシェアや優劣を、出典なしに断定する**       | 「事実上の標準」「デファクト」等。調査会社レポート等の出典がなければ書かない       |
| **東雲デジタル銀行を「遅れている」と読ませる**         | **意図的に慎重にやっている**と本人が明言している。規制業種の制約を怠慢と読ませない |
| **出典のない未来予測**                                 | 「〜は遠い話ではない」等。願望を観測のように書かない                               |

### 想定される反発と、その回避

| 誰から                     | 何を言われうるか               | 回避策                                 |
| -------------------------- | ------------------------------ | -------------------------------------- |
| 取材先ベンダー・パートナー | 事実誤認、名称・数値の誤り     | 数値・名称は一次資料で裏取り           |
| 導入企業                   | 発言の切り取り、意図と違う印象 | 引用は文脈ごと。掲載前確認の約束を守る |
| 読者                       | 提灯記事だ                     | 条件と限界を書く。成功譚にしない       |
| SNS                        | 煽っている、決めつけている     | 断定と序列化を排除する                 |
