# 特集「AI エージェント、実証実験から実務へ」編集方針

**合意日**：2026 年 7 月 25 日
**合意者**：三村 健吾（デスク）／佐倉 涼（担当記者）
**掲載予定**：2026 年 8 月 24 日

> 入稿前に、この方針に照らして自分の原稿を読み返してください。
> 事実が正しくても、方針から外れていれば書き直しになります。

---

## 1. 読者ペルソナ

**情報システム部門の課長クラス（40 代）**

- 予算と人員を握っているが、自分でコードは書かない
- AI エージェントという言葉は知っているが、自社で何ができるかは見えていない
- 読む動機は「**うちのどの業務なら効くのか**」を判断したいから
- ベンダーの宣伝記事にはうんざりしている。売り込まれると閉じる

**この人が読み終わったときに得ているべきもの**
自社の業務のうち、**どれが「効く側」でどれが「効かない側」か**を、自分で仕分けできる基準。

---

## 2. 主題（これ以外に広げない）

> **効果の差を分けるのは製品ではなく、その業務の判断基準が言語化されているかである。**

この一文に貢献しない段落は、面白くても削ります。

**特に注意**：技術の将来像に寄り道しないこと。
本稿は事例記事であり、技術展望記事ではありません。

---

## 3. 技術難易度

| 項目             | 方針                                           |
| ---------------- | ---------------------------------------------- |
| 製品名・専門用語 | 出してよい。ただし**初出で一言の説明**を付ける |
| コード・設定例   | **載せない**                                   |
| アーキテクチャ図 | **入れない**（今回は事例記事）                 |
| 数値             | 出典を明示できるものだけ。**単位を必ず添える** |

「情報システム部門の課長が、部内会議でそのまま説明できる」水準を目安にします。

---

## 4. トーン

- **特定製品を持ち上げない。** 本稿は比較記事ではありません
- **導入企業を「進んでいる／遅れている」で序列化しない。** 業務特性の違いは優劣ではありません
- 成功譚にしない。**効いた条件**と**効かなかった理由**を等しく書く
- 読者が自社に当てはめて判断できる材料を出す

---

## 5. ⚠️ 炎上リスクの回避（今回もっとも注意する項目）

前回の特集で SNS 上の反発を受けた反省を踏まえます。

### 絶対に避けること

| 避けること                                                 | 理由                                                                       |
| ---------------------------------------------------------- | -------------------------------------------------------------------------- |
| **雇用への断定**（「事務職を代替する」「仕事を奪う」等）   | **今回いちばん燃えやすい。** 取材で言われていないことを書かない            |
| **煽り見出し**                                             | 内容と乖離すると、本文を読まない層に切り取られる                          |
| **「〜すべきだ」「〜は間違っている」**                     | 事例記事で説教をしない。判断は読者がする                                  |
| **効果が小さい企業を「遅れている」と読ませる**             | 業務に例外処理が多いだけ。**怠慢と読ませない**                            |
| **取材先の発言を、文脈から切り離して強い主張に見せる**     | 取材先との信頼を毀損する。訂正では回復できない                            |
| **出典のない未来予測**                                     | 「数年内に〜だろう」等。願望を観測のように書かない                        |
| **実在企業の公開事例を、出典を確認せずに引く**             | **社名と数値の取り違えは訂正の最頻出パターン**（COR-2025-0088 参照）      |

### 想定される反発と、その回避

| 誰から       | 何を言われうるか               | 回避策                                             |
| ------------ | ------------------------------ | -------------------------------------------------- |
| 読者・SNS    | AI で仕事がなくなると煽っている | 雇用への言及は取材で得た範囲にとどめる             |
| 取材先       | 発言の切り取り、意図と違う印象 | 引用は文脈ごと。掲載前確認の約束を守る             |
| 効果が小さい企業 | 晒し者にされた                 | 業務特性の違いとして書く。序列化しない             |
| 引用した実在企業 | 事実誤認、数値の取り違え       | **公開事例まとめの出典を開いて確認してから書く**   |

## 6. 入稿前チェック

- [ ] 主題に貢献しない段落が残っていないか
- [ ] **数値に単位が付いているか。** 時間・人時・か月・率が混ざっていないか
- [ ] 出典を示せない断定がないか
- [ ] **雇用への影響を、取材で得た範囲を超えて書いていないか**
- [ ] 導入企業を序列化して読ませていないか
- [ ] **実在企業の公開事例で、社名と数値の対応を出典で確認したか**
- [ ] 引用が文脈から切り離されていないか
- [ ] 掲載前確認が必要な発言を含んでいないか（東雲デジタル銀行）
- [ ] 公表時期に制約のある情報を含んでいないか（東都テレビの並列数の詳細）
