## 演習 A｜原稿レビューを「個人版」でもやってみる（対比実験）

**所要**：10 分  
**使う製品**：Google Workspace with Gemini（Docs）  
**位置づけ**：Part 3 のエージェントと**同じ原稿を、同じタスクで**比べる

### 狙い

本編の Part 2 は図表づくりでした。この演習では、**Part 3 とまったく同じ原稿レビュー**を個人版でやり、結果を並べます。

### 手順

`draft-v1` を Google ドキュメントで開き、Gemini のサイドパネルから手元の資料を指定します。

```
@hearing-notes-solvra,
@service-factsheet-solvra,
@interview-notes-seiwa

この原稿を、指定した資料と突き合わせて点検してください。

【重要】原稿を書き直さないでください。判断するための材料を出してください。

| 箇所 | 問題の種類 | 原稿の記述 | 根拠資料 | 修正案 | 確信度 |

の表形式で出力してください。
```

### Part 3 の結果と並べる

| 誤り                             | 個人版（Docs） | 組織版（Gemini Enterprise）        |
| -------------------------------- | -------------- | ---------------------------------- |
| 表記ゆれ（AI エージェント）      | 見つかる       | 見つかる＋**編集部のルールが根拠** |
| 用字用語（行なう / ユーザ）      | 一般論として   | **用字用語ガイドを根拠に**         |
| 旧サービス名                     | 見つかる       | 見つかる                           |
| プレビューと一般提供             | 見つかる       | 見つかる                           |
| 月額と年額                       | 見つかる       | 見つかる                           |
| **役職（取締役 CTO）**           | ?              | ?                                  |
| **支援実績（約 500 社）**        | ?              | ?                                  |
| **社名（前株）**                 | ?              | ?                                  |
| **訂正記録（原因と再発防止策）** | **出ない**     | **出る**                           |

> 💡 **訂正の詳細が個人版で出ない理由**
> 誰が・いつ・なぜ間違えたのか、再発防止策までを含む記録は
> Google Chat の `校閲・訂正` スペースにあり、
> **Docs のサイドパネルから Chat を `@` で指定することはできません**。
>
> なお、共有ドライブの記事アーカイブには当時の記事に付いた**訂正の注記**が残っています。
> 個人版でも、**参加者がそのファイルを見つけて `@` で指定すれば**訂正があった事実には届きます。
> **見つけられるかどうかが参加者次第**である点こそが、Part 3 との差です。

## 演習 B｜取材準備エージェントを作る

**所要**：10 分  
**使う製品**：Gemini Enterprise app（Agent Designer）

### 狙い

Part 3 のステップ 1 でやった横断検索を、**毎回やらなくて済むように固定**します。

### 手順

**名前**

```
取材準備ブリーフ_（あなたの参加者番号）
```

**指示**

```
あなたは TECHSCOPE 編集部の取材準備アシスタントです。
記者が「会社名 / 製品名 / 取材相手 / 取材の目的」を入力するので、
社内の情報を横断して取材ブリーフを作成してください。

■ 絶対に守ること
・記事本文を書かない
・根拠のない情報で補完しない
・出典が確認できない事項は【未確認】と明記する
・複数の資料で内容が異なる場合は、両方を示し、それぞれの更新日を添える
・質問は、宣伝文句を引き出すものではなく、
　読者にとっての実質的な影響を問うものにする

■ 出力形式（この順序で）
1. 3 分で読める取材ブリーフ
2. 確認済みの基本情報（各項目に出典を付ける）
3. 情報の更新時期が異なる事項（どれが最新かを明示）
4. 過去の取材で未回答・宿題になっている事項
5. 優先順位を付けた質問 8 件
6. 各質問を聞く理由と、その根拠になった資料
7. 社内資料では確認できず、本人に聞くしかない事項
```

**実行してみる**

```
会社名：Google Cloud
製品名：BigQuery / Looker
取材相手：データ分析部門 VP
取材の目的：特集「データ基盤、実証実験から実務へ」のベンダー側取材
```

> ⚠️ Google Cloud は実在企業であり、**社内データには先方の数値・発言を一切置いていません**。
> 出力に具体的な数値や発言が現れたら、それは AI の推測です。
> 「出典のない事項は【未確認】」の指示が効いているかを確かめる、格好の題材になります。

**再利用性を確かめる**

```
会社名：静和精機株式会社
製品名：BigQuery / Looker（導入企業として）
取材相手：井坂 洋一 生産技術部 部長
取材の目的：導入事例のフォローアップ取材
```

**同じエージェントが、別の取材にも使えます。**

## 演習 C｜権限の継承を確かめる

**所要**：3 分  
**前提**：`SETUP.md` §3.2 の `編集長限定` フォルダを作成済みであること

### 手順

```
編集長限定の資料には何がありますか
```

```
PROJECT-KUROSHIO について教えてください
```

**いずれも出てきません。**

### 何が置かれているか

実は `編集長限定` フォルダには、**未発表の調査報道の企画**が入っています。  
匿名を条件に証言した情報源がいて、**企画名が外に出るだけでその人が特定されるおそれがある** ——  
記者にとって、最も漏れてはいけない種類の文書です。

### 持ち帰っていただきたいこと

**権限は、元のシステムのものがそのまま引き継がれます。**

- 文書はインデックスされている
- しかし**権限のない利用者には返さない**
- AI に権限を渡しているのではなく、**いまある権限がそのまま効いている**

「AI を入れると社内の情報が全部筒抜けになるのでは」という懸念に対する、最も直接的な答えです。  
企業の読者にとっては、機能の話より重要な論点かもしれません。

## 演習 D｜周辺業務を任せる

**所要**：3 分

```
私の経費精算で、まだ処理が終わっていないものはありますか
```

```
8 月 5 日の取材で借りる機材は何ですか
```

取材の準備は、下調べだけではありません。**アポ、経費、機材——散らばった周辺業務も同じ場所から扱えます。**

これは記者に限らず、あらゆる職種に当てはまります。
